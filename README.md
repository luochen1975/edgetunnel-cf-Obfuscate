# EDtunnel 使用说明

这是一个基于 Cloudflare Worker 的“IP 收集 + 速度测试 + 优选筛选”工具，核心目标是：

- 从公网/公开来源抓取候选 IP 或域名
- 识别地址、地区、延迟、带宽等信息
- 批量测速并按条件筛选优质地址
- 通过页面或接口导出 `ip.txt`、`quality-ips.txt` 等结果

它本质上不是“把一个 IP 直接变成可用代理节点”的工具，而是一个“优选IP管理和导出平台”。

## 1. 它到底是在做什么？

这个项目的关键代码来自 `明文.js`，里面大量逻辑都围绕下面这些动作：

- 抓取潜在代理 IP / 域名
- 解析地址格式（IPv4 / IPv6 / 域名）
- 识别国家/地区信息
- 批量测速（延迟、速度、可用性）
- 过滤黑名单、白名单、地区限制
- 保存历史记录和优选结果
- 提供 Web 接口，便于查看、更新和导出 IP 列表

也就是说，它更像是“代理IP池管理器”和“优选IP筛选器”，而不是单独的代理协议实现器。

## 2. 优选 IP 和代理节点不是一回事

很多人会混淆：

- 优选 IP = “比较快/稳定的出口地址候选”
- 代理节点 = “客户端可直接使用的 VLESS/Trojan/HTTP 代理配置”

这两个不是等价关系。

例如：

- 你从这个项目得到一个 `203.0.113.10#日本#50ms` 的地址
- 这说明它在测试中表现不错，但它本身不等于客户端能直接使用的 VLESS URI
- 客户端真正要连接的，往往是：
  - 协议（VLESS/Trojan/VMess/WS/HTTP）
  - 服务器地址
  - 端口
  - UUID 或密码
  - TLS/SNI/Host
  - WebSocket 路径

所以：优选了地址，不代表“自动生成节点”；要生成客户端可直接使用的节点，还需要你的代理服务端或订阅生成工具把这些参数整合起来。

## 3. 这个项目能不能直接代理？

结论：最稳妥的理解是：

- 这个项目本身不是“直接可用代理服务端”
- 它提供的是“候选 IP 列表 + 测速筛选 + 导出结果”
- 只有你另外部署了支持 VLESS / Trojan / HTTP 等协议的 Cloudflare Worker 或代理服务，它才可能把这些优选 IP 用在实际代理链路上

如果你已经部署了自己的 `_worker.js`，并且该 Worker 里真正实现了代理协议，那么优选出来的 IP 可能会作为连接入口或回源地址参与实际代理；但如果该 Worker 只是一个测速/采集工具，单纯优选 IP 本身不会自动变成代理节点。

## 4. 从代码结构看，它的真实用途

从项目文件和功能命名可以看出：

- `updateAllAddresses`：更新地址池
- `testIPLatency`：测延迟
- `handleGetIPs`：获取 IP 列表
- `handleGetQualityIPs`：获取优选 IP
- `handleManualSpeedTest`：手动测速
- `handleSetBlacklist`：黑名单管理
- `handleSetSources`：来源设置
- `handleSetQualityCountries`：按国家筛选优选 IP

这些函数都表现出这是一个“地址池管理器”。

而不是：

- `startProxyServer`
- `handleVLESSConnection`
- `handleWebSocketProxy`
- `makeTrojanNode`

从代码逻辑上看，项目重点在数据收集、筛选和导出，而不是在服务端代理协议握手处理。

## 5. 你可以这么理解使用流程

### 方案 A：只做优选 IP

1. 部署这个 Worker
2. 配置 IP 来源（网站/列表来源）
3. 运行更新/测速
4. 导出优选 IP
5. 把这些地址当作候选地址池使用

这个流程适合：

- 需要一个稳定的优选 IP 列表
- 作为其他代理系统的候选入口
- 做地址管理和筛选

### 方案 B：把优选 IP 接到真实代理

1. 先有一个真实的代理服务端，例如 Cloudflare Worker 代理、VLESS/Trojan 服务端
2. 让它支持客户端连接
3. 使用优选 IP 作为连接入口或回源候选
4. 生成客户端节点配置
5. 导入客户端使用

这个流程才是真正“代理使用”场景。

## 6. 常见误区

### 误区 1：导出 `ip.txt` 就能直接用

不是。导出的文本多半是：

```text
1.1.1.1#美国#30ms
2.2.2.2#日本#45ms
```

这只是筛选结果，不是客户端支持的代理节点格式。

### 误区 2：优选 IP = 代理 IP

优选 IP 是“候选地址”，未必提供相同协议、端口、TLS 或 WebSocket 路径。

### 误区 3：Worker 里有测速代码就证明能做代理

测速代码完成的是“访问和测延迟”，不是“代理协议处理”。这两者是不同层面的能力。

## 7. 实际使用建议

如果你的目标是“拿到能直接连的节点”，建议做法是：

- 先确认你部署的 Worker 是否真正实现了 VLESS/Trojan/WebSocket 等协议
- 再将优选 IP 当作该代理服务的入口地址候选
- 如果只是这个项目本身，更多是“优选 IP 管理”而不是“最终代理节点”

如果你的目标是“只获取优选 IP 列表”，那么这个项目是比较合适的。

## 8. 一句话总结

这个项目更像“IP 池质量管理器/优选器”，不是直接可用的代理节点生成器。它能帮助你筛出更好的地址，但要真正实现代理，还需要你自己的服务端协议实现和客户端节点配置。
